# Тестовое задание: характеристики товара

Сейчас без выбранных категорий показаны все характеристики, а после выбора набор характеристик и данные для отправки формируются неправильно. Исправьте это по правилам ниже.

На странице слева находится форма товара, справа — обезличенные тестовые данные MySQL в режиме только для чтения.

## Как должно работать

### 1. Вывод характеристик

- Общие характеристики с пустым `property_s.cat_prop` показываются всегда.
- Характеристика категории показывается, если выбрана хотя бы одна категория из её `cat_prop`.
- ID категорий в `cat_prop` перечислены через запятую.
- Пустой или некорректный `category` не вызывает warning/fatal error и возвращает общие поля.
- Названия, подсказки и варианты из БД выводятся как текст и не интерпретируются браузером как HTML/JavaScript.

При изменении категорий JavaScript отправляет их ID в массиве `category`. PHP возвращает готовый HTML для блока `.property_all`.

### 2. Сохранение введённых значений

Если характеристика остаётся в новом наборе после AJAX-обновления, введённое или выбранное значение не сбрасывается.

Пример проверки: выбрать «Мебель» → заполнить характеристики → добавить «Декор». Заполненные поля должны сохранить значения.

### 3. Проверка отправки

Кнопка «Проверить отправку» ничего не записывает в БД. Она отправляет данные в проверочный PHP-обработчик и показывает полученный результат на странице.

```json
{
  "cats": ["furniture", "decor"],
  "property_mas": {
    "1": "ART-001",
    "2": "2",
    "3": "4:::6",
    "4": "0"
  }
}
```

- `cats` содержит `chpu_category` выбранных категорий.
- Ключ `property_mas` — ID характеристики.
- Текст, число и одиночный выбор передаются строкой.
- ID мультивыбора объединяются через `:::`.
- Пустые и отсутствующие в текущем наборе характеристики не отправляются.
- Числовое значение `0` считается заполненным и отправляется.

## Основные файлы задания

- [`app/public/admin/views/addNewGood.tpl.php`](app/public/admin/views/addNewGood.tpl.php) — первоначальный вывод характеристик;
- [`app/public/admin/js/property.js`](app/public/admin/js/property.js) — обновление после выбора категорий;
- [`app/public/admin/js/main.js`](app/public/admin/js/main.js) — сбор данных по кнопке;
- [`app/public/admin/ajax/property/Refresh_Property_Good.php`](app/public/admin/ajax/property/Refresh_Property_Good.php) — отбор характеристик и HTML-ответ.

Файл [`app/public/admin/ajax/Preview_Good_Payload.php`](app/public/admin/ajax/Preview_Good_Payload.php) только показывает полученные параметры — менять его не нужно.

Сохраните существующие PHP 5.6, MySQL 5.7, jQuery, форматы запросов и DOM-классы. Нельзя менять схему и тестовые данные БД, существующие тесты или подключать frontend-фреймворк. Свои тесты добавлять можно. Конкретный алгоритм выберите самостоятельно.

## Запуск и проверка

Docker — рекомендуемый, но не обязательный способ запуска. Можно использовать собственное локальное или серверное окружение.

Требования к окружению:

- PHP 5.6;
- установленное и включённое PHP-расширение `pdo_mysql`;
- MySQL 5.7;
- корень сайта направлен на `app/public`;
- подключение к базе передано через `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.

### Через Docker

```bash
docker compose up --build -d
```

Откройте `http://localhost:8080`.

```bash
docker compose exec -T web php /var/www/tests/run.php
```

Обе проверки должны пройти: они подтверждают только доступность тестовой базы и HTML-ответ AJAX-обработчика. Функциональные требования этими проверками не оцениваются.

Тестовые данные находятся в [`database/init.sql`](database/init.sql). Посмотреть базу можно справа на странице или через MySQL:

```bash
docker compose exec db mysql -ucatalog_user -pcatalog_password catalog_demo
```

### В своём окружении

1. Создайте пустую базу MySQL и импортируйте [`database/init.sql`](database/init.sql).
2. Передайте приложению параметры подключения через переменные `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.
3. Настройте корень сайта на `app/public` или запустите встроенный сервер PHP из корня репозитория:

```bash
DB_HOST=127.0.0.1 DB_NAME=catalog_demo DB_USER=catalog_user DB_PASSWORD=catalog_password \
php -S 127.0.0.1:8080 -t app/public
```

Smoke-проверки запускаются с теми же переменными окружения:

```bash
DB_HOST=127.0.0.1 DB_NAME=catalog_demo DB_USER=catalog_user DB_PASSWORD=catalog_password \
php tests/run.php
```

Конкретные имя базы, пользователь и пароль могут отличаться. Менять для этого код приложения не нужно.
